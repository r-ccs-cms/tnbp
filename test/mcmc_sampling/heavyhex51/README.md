# Fig. A1 heavy-hex 51-site sampling probe

Graph source: [arXiv:2607.24937v1, Fig. A1, upper panel](https://arxiv.org/pdf/2607.24937v1#page=17).
The figure was visually transcribed, retaining IBM qubit labels. The fixture has
51 vertices, 56 undirected edges, degree histogram {2: 41, 3: 10}, one connected
component and cycle rank 6.

The horizontal chains are 29--33, 47--55, 67--75, 87--95 and 107--115.

- `manual`: reads nine explicit horizontal lines and the explicit group file.
  Groups partition neighboring rows into contiguous geometric intervals nearest
  each target's horizontal coordinate (ties left), with members ordered for
  connected absorption. They are independent of the automatic graph planner.
- `auto`: supplies only `{29,30,31,32,33}` to `bmps_setup_lines`. The resulting
  17 lines and original-graph groups are generated by the public automatic APIs.

All input files are in `data/`. Both plans pass the shared validator. The probe
prints every line/group before validation so failures can be diagnosed.

## Test state

The complex-double PEPS exactly represents

```text
[product Ry(beta)] [product over all edges RZZ(gamma)]
[product Ry(alpha_i)] |0...0>
alpha_i = 2 asin(sqrt(p_i)), p_i = 0.25 + 0.08 (i mod 5)
beta = 0.37, gamma = 0.24, i = ascending-label site position
```

All ZZ gates commute; the graph has a three-layer matching decomposition. This
is one weak ZZ interaction round with single-site preparation/final rotations,
not a reproduction of the paper's Floquet parameters or many-cycle dynamics.

Virtual dimension 2 uses the exact edge expansion
`RZZ(gamma) = cos(gamma/2) I*I - i sin(gamma/2) Z*Z`.
Each endpoint contributes square roots of these coefficients. The physical axis
is last; virtual axes follow edge order. Tensor construction uses TCAPI.
Dimension 1 sets gamma=0 and is an exact product-state control.

The exact single-site probability is available without a 2^51 statevector:

```text
z_i = (1-2p_i) cos(beta)
      - 2 sqrt(p_i(1-p_i)) sin(beta)
        Re product_{j adjacent i} [(1-p_j) exp(-i gamma) + p_j exp(i gamma)]
P_i(1) = (1-z_i)/2
```

These marginals are reported as diagnostics, not a precision pass/fail threshold:
MCMC observations are correlated and small boundary caps can introduce bias.
The output `SAMPLING COMPLETED` indicates successful execution, not
distributional correctness.

## Build and run

Build targets `heavyhex51` and `heavyhex51_product_reference` with the CPU or CUDA
configuration of the [common test entry point](../../README.md#build-and-run).
The commands below illustrate CPU launches; CUDA requires an allocation with
one visible GPU per MPI process.
Use one OpenMP/BLAS thread. Arguments:

```sh
mpirun -np 1 <build>/heavyhex51 <repo>/test/mcmc_sampling/heavyhex51/data manual 2 64 2
mpirun -np 1 <build>/heavyhex51 <repo>/test/mcmc_sampling/heavyhex51/data auto   2 64 2
# chi=0: planning only; D=1: product control
mpirun -np 1 <build>/heavyhex51 <repo>/test/mcmc_sampling/heavyhex51/data auto   0 1  2
mpirun -np 1 <build>/heavyhex51 <repo>/test/mcmc_sampling/heavyhex51/data manual 1 16 1 uniform
```

The arguments are mode, boundary cap, retained sample count and virtual dimension;
`uniform` optionally chooses p_i=1/2, beta=gamma=0. All runs start at all-zero bits
and discard 16 stored samples. BP limit 10, tolerance 1e-9, singular-value cutoff
1e-12 and truncation target 1e-10. Ownership is ascending-site index modulo rank
count. Random seed is 7129+rank. Every retained bitstring is printed.

## Metropolis periodicity for uniform states

With the default Metropolis method, the uniform control executes successfully
but produces all-zero retained samples in both grouping modes, rather than the
uniform distribution. The proposal for a binary
site always flips it. Every flip is accepted for this state. Each stored sample
follows a forward and backward sweep, so every bit has flipped twice and returns
to its original value. More burn-in or a larger boundary cap cannot cure this
exact periodicity. Near probability 1/2, the same mechanism can give long
correlation times. Use the `heatbath` option below for the uniform product-state
control: its pairwise transition probability is 1/2, avoiding this deterministic
flip cycle. Normal completion alone does not establish sampling accuracy.

## Validation scope

The fixture has been run on CPU and CUDA at MPI 1/2 ranks (same-node GPUs).
GPU heat-bath runs use 64 retained samples for manual/automatic grouping with
uniform D=1, nonuniform D=1, and D=2. All D=1 bitstrings match the independent
scalar reference. D=2 checks completion, sample structure and finite marginals;
it does not establish distributional accuracy. Deep circuits, large virtual
dimensions and production accuracy remain outside this probe's scope.

## Independent product-state reference

`heavyhex51_product_reference <probe.log>` uses only scalar probabilities and
standard C++ random generators (no TNBP or TCAPI). It simulates the same proposal,
acceptance and forward/backward visit order, with one generator per owning rank,
and compares every retained bitstring. D=1 manual/automatic checks cover
MPI 1/2 ranks. This separates
contraction/ownership correctness from the periodicity of the update kernel.

`python3 check_samples.py <probe.log>` checks completion and 51-bit sample output.
Add `--uniform` to reject all-identical samples from a uniform-state run.
The default Metropolis method fails this check for both grouping modes because
of the periodicity described above. Neither scalar-reference agreement nor
normal completion proves that the transition kernel mixes.

## Heat-bath option

Append `heatbath` to the probe command to use sampling method 1; it can be
combined with `uniform`. For example:

```sh
mpirun -np 1 <build>/heavyhex51 <data-dir> auto 1 512 1 uniform heatbath
python3 check_samples.py <log> --uniform --accuracy
<build>/heavyhex51_product_reference <log>
```

The independent scalar reference reads method and uniform-state metadata from
the probe log. For D=1 it checks every
complete retained bitstring. `--accuracy` additionally bounds the largest
single-site marginal error by `3/sqrt(N)`; use this independent-sample bound
for heat-bath product controls, not as a general correlated-chain guarantee.
